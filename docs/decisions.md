# Принятые решения

Для каждого решения фиксируем дату, контекст, само решение и последствия.

## 2026-11-06 — ночная фотография как фон всего сайта

- **Контекст:** требуется обновить визуальный стиль сайта и использовать в оформлении ночной вид Дананга.
- **Решение:** современный стиль применяется на всех страницах. Фоном служит ночная фотография моста Тхуан Фыок через реку Хан, опубликованная на Wikimedia Commons автором Thick thi sock по лицензии CC BY-SA 3.0. Точка съёмки из Blooming Tower не подтверждена. На сайте размещается атрибуция со ссылками на источник и лицензию.
- **Последствия:** фон кадрируется под экран и затемняется для читаемости. Атрибуция остаётся видимой на всех страницах сайта.

## 2026-11-06 — фиксированное смещение магазина относительно UTC

- **Контекст:** ввод IANA-кода часового пояса в настройках магазина оказался неочевидным.
- **Решение:** главный администратор выбирает фиксированное UTC-смещение из выпадающего списка. В подписи варианта указываются смещение и примеры локаций; доступен диапазон UTC−12:00…UTC+14:00 с шагом 15 минут. Для Москвы используется UTC+3.
- **Последствия:** расписание, прибытие покупателя и длительность брони рассчитываются с учётом выбранного фиксированного смещения. Автоматический сезонный перевод времени не выполняется; при необходимости администратор меняет смещение вручную.

## 2026-10-28 — магазины имеют отдельные настройки

- **Контекст:** в системе может быть несколько магазинов, которыми управляют назначенные администраторы.
- **Решение:** товар и заявка относятся к одному магазину; валюта, расписание работы, адрес передачи товара, длительность брони и сетка комиссий настраиваются отдельно для каждого магазина.
- **Последствия:** каталог и форма заявки должны позволять выбрать магазин, а расчёт сроков и комиссии выполняется с учётом настроек выбранного магазина.

## 2026-10-28 — бронирование не требует регистрации

- **Контекст:** покупатель может забронировать товар из каталога без создания аккаунта.
- **Решение:** бронь создаётся без регистрации; покупатель обязательно указывает время прибытия, а имя, телефон и email может оставить по желанию. Длительность брони отсчитывается от момента создания и считается в рабочих часах магазина. Действующую бронь нельзя отменить или продлить; после истечения срока товар автоматически возвращается в продажу, и его можно забронировать снова.
- **Последствия:** бронь должна показывать время окончания; расписание магазина используется для проверки времени прибытия и подсчёта срока от момента создания брони в рабочих часах. Бронирование отклоняется, если выбранное время прибытия позже окончания брони.

## 2026-10-28 — покупатель бронирует, продажу фиксирует администратор

- **Контекст:** в текущей постановке описана бронь товара, но не оформление и оплата онлайн-заказа.
- **Решение:** система не проводит оплату покупателя. После фактической продажи администратор меняет статус товара на «Продано».
- **Последствия:** правила онлайн-оплаты и доставки покупателю не входят в текущий объём требований.

## 2026-10-28 — комиссия задаётся для каждого магазина

- **Контекст:** ставка зависит от магазина и цены товара.
- **Решение:** главный администратор задаёт ценовые пороги и ставку для каждого порога. Ставка может быть процентом от цены продажи или фиксированной суммой в валюте магазина. Администратор магазина может вручную указать для заявки произвольную процентную ставку. Нельзя отправить заявку с ценой ниже минимального порога магазина. Выплату продавцу отмечает администратор.
- **Последствия:** при автоматическом выборе применяется ставка с наибольшим порогом, не превышающим цену товара; сумма продавцу равна цене продажи за вычетом комиссии. Срок выплаты не регламентируется.

## 2026-10-28 — уведомления о статусах отправляются по email

- **Контекст:** email подтверждается при регистрации и служит каналом системных уведомлений.
- **Решение:** при каждом изменении статуса заявки, принятого товара и выплаты продавец получает уведомление на email. Выбранный при регистрации мессенджер предназначен только для ручной переписки с администратором.
- **Последствия:** автоматические уведомления через мессенджеры не требуются.
